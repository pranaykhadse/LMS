Each subdirectory is an independent Flutter desktop target generated by `flutter create`, providing a native executable that hosts the Flutter engine:
- `linux/`: CMake-based project using GTK3/GNOME; `runner/main.cc` creates a `MyApplication` subclass of `GApplication` and runs via GLib; `CMakeLists.txt` configures install bundles with RPATH `$ORIGIN/lib`, includes `flutter/generated_plugins.cmake`, and installs the Flutter AOT library and assets.
- `windows/`: CMake + Win32 project; `runner/main.cpp` implements `wWinMain`, initializes COM, constructs a `DartProject` pointing at `data/`, creates a `FlutterWindow` backed by `Win32Window`, and runs the Win32 message loop; resources are embedded via `Runner.rc` / `resource.h`.
- `macos/`: Xcode project (`Runner.xcodeproj`) built with Cocoa; `AppDelegate.swift` extends `FlutterAppDelegate` and sets termination/restorable-state behavior, while `MainFlutterWindow.swift` owns the Flutter view; build configs live under `Runner/Configs/*.xcconfig` and CocoaPods integration is declared in `Podfile`.
All three share the same dependency direction: native runner → Flutter engine/Dart project → plugin code auto-generated under `flutter/ephemeral/` (`generated_plugin_registrant.*`, `generated_plugins.cmake`).
